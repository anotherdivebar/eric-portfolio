## <span id="start-with-the-input">When the rule can’t pick a rep</span>

<p id="where-this-approach-applies">Sometimes a field is blank. Sometimes two entries disagree. When the tool can’t pick a rep, it puts the request in a queue for the team to review. It also saves the rule behind each assignment, so if a request goes to the wrong person, we can see why.</p>

## <span id="connect-the-signal-to-an-action">When the response is overdue</span>

Once a rep gets a request, a timer starts. If they miss the deadline, the tool flags the request for follow-up.

## <span id="review-the-exceptions">Fixing a record or changing the rule</span>

If a request is missing a detail, the team can fix the customer record. If the details are right and the wrong rep keeps getting the requests, the rule needs to change. I built an admin screen so the team can do that without waiting for me to release new code.
