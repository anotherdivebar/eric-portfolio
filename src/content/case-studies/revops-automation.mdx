## Where this approach applies

A renewal alert is easy to overlook when it lands in a shared inbox. I design the rule around what a person needs to do next, then work backward to the information that should trigger it.

## Start with the input

I check records for missing or inconsistent details before sending them to the next team. Sales and support need to agree on what the fields mean. If a record is incomplete, I send it for review instead of guessing who should receive it.

## Connect the signal to an action

For a pipeline change or upcoming renewal, the alert should say what changed, who should follow up, and when a response is due. If the deadline passes, the workflow shows the overdue item and who can help resolve it.

## Review the exceptions

I review missed handoffs with the team. An incorrect customer record calls for a data correction. If valid records keep reaching the wrong person, we need to change the rule.
