## <span id="start-with-the-input">When the rule can’t pick a rep</span>

<p id="where-this-approach-applies">A blank or inconsistent CRM field can leave a request without an owner. The service keeps that request in the exception queue. It also logs routing decisions so staff can trace how a request reached a particular rep.</p>

## <span id="connect-the-signal-to-an-action">When the response is overdue</span>

Once a request has an owner, a timer tracks how long the rep has to respond. If the deadline passes, the escalation rule flags the missed follow-up.

## <span id="review-the-exceptions">Fixing a record or changing the rule</span>

A missing field calls for a correction to the customer record. If complete records keep reaching the wrong rep, staff can change the policy in the admin interface without waiting for a code release.
