## What I built

LeakLens is a revenue leak recovery product demo built to show how operators could find stalled quotes, dormant accounts, and follow-up gaps before they turn into lost revenue.

The work spans both sides of the funnel: a marketing site that explains the problem, followed by demo onboarding and an app workspace with connector management, leak triage, recovery workflows, and reporting.

## Demo scope

The workspace uses seeded data for a fictional field-services company. Connectors and API responses are simulated, and changes persist in memory for the running session. The app shell illustrates the signed-in experience; it is a product demo, not a deployment connected to customer CRM or billing systems. Export and share actions are intentionally stubbed.

## The operator workflow

1. **Understand the inputs.** Connector and intake views show where revenue signals would enter the workspace.
2. **Triage the queue.** Leak views organize stalled quotes, dormant accounts, and follow-up gaps for review.
3. **Choose a recovery path.** Playbooks give the operator a structured next step after identifying an issue.
4. **Review the outcome.** Reporting views demonstrate how recovery activity could be connected to business results using the seeded demo data.

## Implementation choices

Typed Next.js route handlers provide the mock API layer. Zod validates contracts, and React Query manages data access in the interface. That separation makes the screens behave like a connected application while keeping the demonstration self-contained.

Command-palette navigation, keyboard support, and responsive layouts support movement between views. Playwright smoke tests exercise the product flow so changes can be checked beyond a static visual review.

## What this work demonstrates

LeakLens shows my approach to turning a business problem into a navigable product: explain the value, make the inputs visible, give operators a useful review queue, and connect the next action with reporting. Its outcome is the working demonstration and interaction design, not measured revenue recovery.
