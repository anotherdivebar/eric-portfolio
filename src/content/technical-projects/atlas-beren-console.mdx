## Overview

Atlas-Beren Console is the internal operating system behind Atlas-Beren's managed workflow installs. It brings client workspaces, AI agent rollout, data intake, readiness gates, approvals, integration status, risk visibility, value tracking, and prospecting into one controlled environment.

The core loop is simple:

`Today -> client workspace -> readiness -> agent run -> evidence review -> approval -> action -> visibility`

Instead of treating AI agents as magic boxes, the console treats them like operational systems: they need context, evidence, constraints, approval paths, audit trails, and measurable business value.

## Problem

One operator managing clients, workflow automations, AI agents, integrations, prospecting, and follow-up cannot rely on disconnected spreadsheets, dashboards, browser tabs, and one-off scripts.

The real risk is not just missed work. It is invisible work.

Stale follow-up, incomplete intake, broken integrations, unreviewed outputs, weak evidence, and unclear ownership all create operational drag. Atlas-Beren Console was built to keep those gaps surfaced before they become client-facing problems.

## Approach

The console is catalog-driven. Agents are not stored as loose prompts or vague automation ideas. Each agent carries operational metadata: purpose, runbook, required evidence, readiness criteria, KPIs, risk notes, and limits.

Client workspaces track the context needed to make those agents useful: intake data, unified profiles, source material, integration status, activity, approvals, and follow-up actions. Prospect Finder sits inside the same system, which means growth work and client delivery share the same discipline around qualification, review, and next steps.

The design principle was simple: AI should accelerate the operator, not bypass the operating model.

## What shipped

- **Client workspaces** with per-client agents, CSV intake, unified profiling, evidence gates, readiness checks, activity history, approvals, and post-approval actions.
- **Agent catalog** with 30+ operator-facing agents across readiness, client operations, revenue recovery, growth, prospecting, governance, and cost control.
- **Operator Today view** ranking client work, failed runs, pending approvals, integration health, stale follow-ups, and prospecting tasks in one morning queue.
- **Integration control panel** with masked environment-backed status for AI Gateway, GCP/Vertex, Places, Hunter, HubSpot, n8n webhooks, GCS, and scheduled feeds.
- **Prospect Finder** for local/company discovery, AI-generated account briefs, optional enrichment, pipeline tracking, and approval-first outbound preparation.
- **Governance layer** with human approval for external actions, mock versus live run separation, readiness override logging, and estimated versus verified value tracking.
- **Owner visibility views** that turn the same operational queues into status, risk, and next-action reporting without rebuilding updates by hand.

## Architecture

Supabase handles authentication, role-gated access, row-level security, and Postgres-backed state. Vercel handles deployment, scheduled checks, and lightweight operational monitoring. Integration status is metadata-first and environment-backed, with sensitive details masked from the browser.

Live agent execution can route through Vercel AI Gateway, while optional GCP services support heavier workflows like document processing, model execution, storage, and analytics when needed. The architecture is intentionally staged: demo-safe, operator-safe, and production-conscious without pretending the system is more mature than it is.

## Lessons learned

- Evidence beats autonomy. An agent is only useful if the operator can trust what it used, what it produced, and what should happen next.
- Human approval is not friction. For business-critical workflows, it is the control layer that makes AI usable.
- Integration health belongs in the operator's daily workflow, not buried in a settings page.
- Metadata-first agent design is more durable than a pile of prompts.
- Prospecting, recovery, and delivery work better when they share the same system of readiness, review, ownership, and action.
- The best AI workflow systems do not remove the operator. They make the operator dramatically more effective.

## What is next

- Per-client Prospect Finder partitioning for cleaner separation between Atlas-Beren growth work and client-assigned prospecting workflows.
- Live integration probes beyond env and metadata checks.
- Encrypted secret registry when the current environment-backed approach becomes the limiting factor.
- Deeper value verification loops connecting agent activity to actual recovered revenue, saved time, or generated pipeline.
